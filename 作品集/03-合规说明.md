# 合规与数据说明

> 一句话：**本作品集不包含任何前雇主的门店影像、系统截图或内部数据。** 这不是遗憾，是应该做的事。

---

## 一、为什么不附门店照片和系统截图

这个项目的实验使用了真实巡店照片与内部巡店系统的界面。但它们：

| 材料 | 为什么不能公开 |
| --- | --- |
| 门店巡店照片 | 含门店现场、品牌标识、可能含顾客与员工影像，属前雇主商业资产与个人信息 |
| 巡店系统截图 | 含内部系统结构、真实人名、门店名、业务字段 |
| 巡店检查表原文 | 属内部标准化文件 |

我已离职，**不再持有这些材料的使用授权**。因此：

- 作品集内**不放**这些材料
- 这些材料**不进入**任何公开仓库、博客、演示或简历附件
- 已在本地单独的私有目录中归档，仅作个人复盘，不对外

---

## 二、我在工作过程中做的数据处理

即便在项目进行期间，也遵循了以下原则：

| 处理 | 做法 |
| --- | --- |
| 含清晰人脸的样本 | **主动排除**，不送入外部模型 API（12 张可用样本中排除了 2 张含顾客面部的照片） |
| 送出外部 API 的确认 | 在使用前**先向业务方确认**照片可否送出外部多模态模型；确认后才执行 |
| 数据落地 | 只使用国内可合规调用的模型服务；照片不写入日志、不用于模型训练 |
| 密钥管理 | API Key 只存本地 `.env`（已加入 `.gitignore`），不进代码、不进仓库、不写入任何文档或日志 |
| 照片体积处理 | HEIC 转 JPG 并缩放至长边 1600px，避免原始大图外传与无谓的调用成本 |

## 三、作品的数字为什么仍然可信

这里有一个容易混淆的点值得说清：

**本作品集引用的核心指标，都不依赖前雇主的照片或内部数据。**

| 引用的指标 | 为什么不受影响 |
| --- | --- |
| 结论一致性 91.7% | 模型自己跟自己比（同一张照片多次推理），不需要人工基准 |
| 单次采样层号噪声率 13.3% | 同上 |
| 模型 0 次主动标"不确定" | 客观计数 |
| 层级准确率 60% | 这是**方法演示**：说明评分体系、混淆矩阵、层级比对怎么设计。数值来自小样本，已在报告中明确声明局限 |

**因此**：作品集展示的是**方法与判断过程**，而不是"我在某公司做出了某个成绩"。前者的可验证性更强——面试时可以当场讲清每一步是怎么算出来的。
