# AI 巡店系统 · 作品集

> 一个**单功能**的 AI 产品案例：从业务口径定义，到技术可行性验证，到依据实测数据推翻自己的产品设计。

---

## 这是什么

某休闲零食连锁品牌的门店 AI 巡店项目。我负责其中的**一个检查项**——「**排面缺货识别**」（`SHELF_OOS`）的完整产品设计。

核心工作不是"做了一个 AI 功能"，而是：

> **把运营侧一句模糊的"货架没摆满"，翻译成模型可执行、专员可复核、数据可验收的完整口径，然后用真实数据验证它到底能不能跑通——并在数据说"不行"的时候改掉自己的设计。**

---

## 结果摘要

用 2 家真实门店、12 张巡店照片完成可行性验证（每张 3 次采样，共 36 次模型调用）：

| 维度 | 实测结果 | 产品含义 |
| --- | --- | --- |
| 判断"有没有缺货" | 结论一致性 **91.7%** | 可靠 —— 可以承担"从一堆照片里挑出有问题的" |
| 判断"缺的是哪一层" | 层级准确率 **60%** | **不可靠 —— 原设计要求"按货架层报告"，被数据推翻** |
| 单次调用可用性 | 层号噪声率 **13.3%** | 单次调用不可采信，必须多次采样取多数 |
| 模型主动认怂 | 36 次判定中 **0 次**标"不确定" | 安全阀必须由产品侧强制，不能靠模型自觉 |
| 检查项边界 | 越界项只进备注、不进判定 | 用提示词把边界写清，模型能守住 |

**最重要的产出不是这些数字，而是**：原设计"AI 给出缺货层号" → 实测 60% → 改为"**AI 定位到证据照片与区域，层号降级为辅助提示**"。
