# 排面缺货识别 · 效果验证实验

## 这个实验要回答什么

**在写任何产品代码之前，先验证一件事：2025 年的多模态模型，能不能稳定识别出门店照片里的「排面缺货」。**

这是整个项目唯一可能致命的假设（见 PRD 第 6 节）：

- VLM 对「连续几个空位」这种**带计数的判断本身不稳**；
- 对偏暗、反光、斜拍的照片**误报率会明显上升**；
- 同一张图**多次推理可能给出不同结论**。

如果实测下来误报率过高或结论不可复现，那这个功能的产品逻辑就要改（只报高置信的少数问题，或者换检查项），甚至不该做。花一两天验证，避免花两周做一个不成立的产品。

## 实验不做什么

- 不接入任何公司内部系统（任务、图片中心、整改链路都不碰）
- 不做界面（这一步只需要命令行跑出数字）
- 不预设"准确率 95%"这类目标数字——数字由真实标注对比得出

## 环境准备

已就绪（本机已验证）：Python 3.12.14 + 独立虚拟环境 `.venv`，依赖 `dashscope / pydantic / pytest`。

```bash
cd experiment
cp .env.example .env          # 把百炼 API Key 填进 .env
```

> **Key 只填进 `.env`**（已在 `.gitignore` 中排除）。不要贴在对话里、不要截图、不要提交。
> 没有 Key 时脚本会自动进入 dry-run，用模拟响应验证流程。

## 需要准备的两样东西

| 材料 | 要求 |
| --- | --- |
| **真实门店照片** | 10 家门店、每家 20～30 张，覆盖社区店/商圈店、正常/偏暗/反光、含遮挡与不含遮挡。放进 `data/photos/`，命名建议 `{门店编号}_{序号}_{说明}.jpg` |
| **API Key** | 阿里云百炼，填入 `.env` 的 `DASHSCOPE_API_KEY` |

## 怎么跑

```bash
# 1) 不花钱先验证流程（用模拟响应）
.venv/bin/python -m oos_check.run --dry-run

# 2) 先试跑 5 张，确认能正常调用
.venv/bin/python -m oos_check.run --limit 5 --samples 1

# 3) 正式跑：每张采样 3 次（用于测结论一致性）
.venv/bin/python -m oos_check.run

# 4) 换了模型/门槛再跑一次做对比
.venv/bin/python -m oos_check.run --model qwen-vl-plus-latest --min-gaps 4
```

跑完在 `output/` 得到三份产物：`raw_*.jsonl`（每次调用的原始结果）、`report_*.md`（人看的汇总）、`report_*.json`（机器可读）。

## 怎么标注（算准确率必须做）

复制 `data/reviews/reviews.example.csv` 为 `data/reviews/reviews.csv`，按下面格式填：

```csv
photo,has_oos,note
A012_01.jpg,是,第2层连续5个空位
A012_02.jpg,否,排面正常
A012_03.jpg,是,偏暗但确实缺货
```

`has_oos` 支持 `是/否` 或 `1/0`。**至少 2 名专员各标一遍**，因为不同专员对"缺货"的尺度本身有差异——这个差异率决定了判定口径要不要写得更细。

## 结果怎么读

| 指标 | 回答什么问题 | 不达标怎么办 |
| --- | --- | --- |
| **结论一致性** | 同一张照片跑多次结论是否一样（方案稳不稳） | 低于 80%：规模一放大会变成大量申诉与返工，先查提示词，再考虑换模型 |
| **精确率** | 报出来的缺货有多少是真的（专员会不会被误报烦到弃用） | 偏低：提高判定门槛、补充"不算缺货"的反例说明 |
| **召回率** | 真实缺货有没有被漏掉 | 偏低：查漏检集中在哪类照片（往往是光照或角度） |
| **照片不可用占比** | 多少照片模型自己认为判断不了 | 偏高：这些情况应排除出识别范围或强制标"不确定" |
| **误报/漏检的具体条目** | 错在哪（看 `raw_*.jsonl`） | 定位到具体门店形态与光线条件，写进检查表的排除项 |

**重要原则**：数字不达标时，改判定门槛与提示词重跑，**不要为了让数字好看去改标注**。

## 目录结构

```
experiment/
├── oos_check/
│   ├── config.py     环境与参数（密钥只从环境变量读）
│   ├── prompt.py     提示词 = 业务判定口径，改口径改这里
│   ├── schema.py     模型返回的严格结构定义与校验
│   ├── client.py     模型调用：超时/重试/结构校验/兜底/dry-run
│   ├── metrics.py    一致性、精确率、召回率、混淆矩阵
│   └── run.py        命令行入口
├── tests/
│   └── test_pipeline.py   16 项自检（不需要 Key 和照片）
├── data/photos/      放真实照片（不进仓库）
├── data/reviews/     放人工标注（不进仓库）
└── output/           跑完的结果（不进仓库）
```

## 自检

```bash
.venv/bin/python -m pytest tests -q
```

覆盖三类容易出错的地方：模型返回的脏格式（markdown 围栏、前后带解释、层号返回成数字）能否正确解析；不合格返回是否被结构校验挡住；一致性/误报/漏检的计算是否正确。
