| 项 | 内容 |
| --- | --- |
| 日期 | 2026-09-24 |

## 一、先说型号问题（已解决，但值得记下来）

首次调用直接 **403 AccessDenied**。原因不是 Key，而是**型号名**。实测你的账号可用情况：

| 型号 | 结果 |
| --- | --- |
| `qwen-vl-plus` | ✓ 200 |
| `qwen-vl-max` | ✓ 200 |
| `qwen-vl-max-latest` | ✗ 403 AccessDenied |
| `qwen-vl-plus-latest` | ✗ 403 AccessDenied |
| `qwen2.5-vl-7b-instruct` | ✗ 403 AccessDenied |
| `qwen2.5-vl-72b-instruct` | ✗ 403 AccessDenied |
| `qwen-vl-max-2025-04-08` | ✗ 403 AccessDenied |

**教训**：「最新版」型号名在百炼上不一定对当前账号开通。**换账号或换项目前，先用 `python -m oos_check.probe` 探一遍**，别直接跑全量。已加 `probe.py` 避免以后再踩。

## 二、实测数字（含重要说明：基准不可信）

### 批次 A：`S01_全量`（8 张，我判"无缺货"）

| 指标 | 结果 |
| --- | --- |
| 模型调用 | 24 次，失败 0 |
| 单张耗时 | 7.7～11.8 秒 |
| **结论一致性** | **75.0%**（8 张里 2 张三次采样结论不一致） |
| 可用性标记稳定率 | 100%（没有一次乱标"照片不可用"） |
| 准确率 | 87.5% |

### 批次 B：`高价值样本`（4 张，我判 3 张"有缺货"）

| 指标 | 结果 |
| --- | --- |
| **召回率** | **0%**（3 张疑似缺货全部漏掉） |
| 结论一致性 | **100%**（稳定地漏，不是随机波动） |
| 图片不可用标记 | 0 次 |

⚠️ **这组数字有两个大坑，都不能直接用**：
1. **基准是我自己标的，已证实会标错**（见第三节）。修正标注后，同样的模型同样的照片，指标从"召回率 0%"变成"召回率 100%"。
2. **`has_oos` 是二元字段，容不下"不确定"**。按评估方案的设计，"不确定"应当是独立选项并由业务裁决；当前实现把非"是"一律当"否"，指标会被标注误差放大。

**修正标注后的对照（同一批 8 张，单次采样）**：

| 指标 | 修正前（错误基准） | **修正后** |
| --- | --- | --- |
| 准确率 | 87.5% | 87.5% |
| 召回率 | **0%** | **100%** |
| 精确率 | **0%** | **50%** |
| 误报／漏检 | 1 ／ 0 | 1 ／ 0 |

也就是说：**模型实际抓到了 2 处真缺货（IMG_1986、IMG_2127），只误报 1 张（IMG_2117）。** 同一个模型、同一批照片，只因为基准标注改了几行，结论就从"完全不可用"变成"有苗头"。

**这一条本身就是本轮最重要的方法论发现：在没有独立人工基准之前，任何准确率数字都是垃圾。** 宁可不报数，也不要报一个基准不可信的数——报出去的数字如果被追问"基准谁标的"，项目就崩了。

## 三、最重要的发现：我的标注是错的

复核照片后确认：

| 照片 | 我的原判 | 复核后的判断 | 结论 |
| --- | --- | --- | --- |
| **IMG_1986** | 无缺货 | **确实有缺货**：中层有一块明显凹陷的黑色空缺，与周围密集商品形成对比 | **模型 3 次全判"有缺货／第 5 层／3 个位／high 置信"——模型是对的，我错了。这不该算误报。** |
| IMG_2092 | 有缺货（低置信） | **购物篮与塑料袋挡住大片区域，无法确认** | 应标"不确定"，我原判太武断 |
| IMG_2125 | 有缺货（中置信） | 复核后不确认有连续 3 个空位 | 我的标注存疑 |
| IMG_2123 | 有缺货（中置信） | 复核后不确认有连续 3 个空位 | 我的标注存疑 |

**所以真实情况是：模型在我标"有问题"的照片上可能是对的，在我说"没问题"的照片上抓到了一个我真的漏看的缺货。**

**这条的产品意义比任何指标都大**：连一个盯着照片逐张分析的产品经理都会看错、会漏看——**这恰好是"排面缺货识别"这个功能存在的理由**。以后讲这个项目，"我作为产品经理亲自标注都标错了"是比"准确率 87.5%"更有说服力的开场。

## 四、发现 1：模型对"不确定"几乎不标注

**模型在 12 张 × 3 次采样 = 36 次判定里，`uncertain` 返回 0 次。**

但 IMG_2092 被购物篮和塑料袋遮挡了大片货架——**这应该是典型的"不确定"场景**，模型却说"陈列饱满，未发现空位"，没有标注任何不确定。

**这直接打在 PRD 的核心设计上**：PRD 第 3、4 节把"无法判定就标不确定"当成产品安全阀（决策 F3）。实测证明**模型默认不会主动认怂**，它倾向于给一个确定的结论。

**产品对策**：不能靠模型自觉，要**在结构上强制**。例如在提示词里要求先逐层输出"可见／被遮挡／看不清"，再给结论；或对返回为空但画面质量评分偏低的照片，由产品侧兜底标"不确定"。

---

## 五、发现 2：结论确实会漂，一致性只有 75%

批次 A 的两张不一致都是同一个模式——**3 次里 2 次说无、1 次说有，且那次报得很自信**：

| 照片 | 采样 1 | 采样 2 | 采样 3 |
| --- | --- | --- | --- |
| IMG_2117 | 无 | 无 | **有**（右侧第 1 层 3 个位，high 置信） |
| IMG_2127 | 无 | **有**（左侧第 3 层 3 个位，high 置信） | 无 |

**这正是 PRD 第 4 节第 6 条「一致性检查」要抓的东西，现在有了实测值：75%。**

**产品含义**：
- 单次调用的结论**不能直接采信**——约 1/3 的调用会给出与多数不一致的判定，而且是"高置信"地给。
- 多次采样取多数的策略是**必需的**，不是优化项。
- 但采样 3 次成本 ×3，且一致性 75% 意味着**单车误报无法靠采样完全消除**，必须靠专员复核兜底——这反过来验证了"AI 初筛 + 人工复核"的产品定位是对的。

## 六、发现 3：模型确实在看图（门槛敏感性测试推翻了我的怀疑）

批次 B 的 12 次返回措辞几乎完全一致，且"连续3个及以上空位"这个短语直接来自我提示词里的门槛——我一度怀疑模型只是在迎合提示词、复读期望答案。

**做了门槛敏感性测试：同一批 8 张照片，门槛分别设为连续 2 / 3 / 5 个空位，各跑一遍。**

| 照片 | k=2 | k=3 | k=5 |
| --- | --- | --- | --- |
| IMG_1947（进口零食/潮玩） | 无 | 无 | 无 |
| **IMG_1985**（散称零食中景） | **有** | 无 | 无 |
| **IMG_1986**（袋装零食正面） | **有** | **有** | **有** |
| **IMG_2117**（饮料冰柜区） | **有** | 无 | 无 |
| IMG_2122（袋装零食斜拍） | 无 | 无 | 无 |
| IMG_2126（方便面区） | 无 | 无 | 无 |
| **IMG_2127**（方便面区斜拍） | **有** | 无 | 无 |
| IMG_2129（饼干糕点区） | 无 | 无 | 无 |

**结论：模型对门槛敏感，说明它确实在估计空位个数，不是单纯复读提示词。** 我原先的怀疑被推翻。

**但暴露了新的、更棘手的问题**：门槛从 3 改成 2，就有 3 张照片从"无缺货"翻成"有缺货"；改成 5，只剩 IMG_1986。也就是说——

> **模型对"到底是 2 个空位还是 3 个空位"的判断很不稳。而判定门槛恰恰定在 2/3 这个边界上。**

这是 2025 年 VLM 计数能力的直接体现：它能"看出那里空了一块"，但**数不准有几个位**。而业务的判定门槛正好卡在这个它数不准的区间。

**产品含义**：
- 判定门槛不能只在提示词里"告知"，必须**在代码里做二次判定**（现在 `below_threshold()` 就是这么做的）。
- 门槛定在 3 意味着**产品选择"宁可漏报、不要误报"**——实测数据显示 k=3 时只有 IMG_1986 被判有问题，而它经复核确实是真缺货。**这个门槛设置是合理的**。
- 但如果业务需要抓到 IMG_1985/2117/2127 那类"2 个位"的轻微缺货，**当前模型能力做不到可靠区分**，不该承诺。

### 另外：多次采样是不是在浪费钱

单次采样（k=3 那轮）8 张耗时 2.2～3.6 秒／张；3 次采样（批次 A）是 7.7～11.8 秒／张，约 3 倍。

但 3 次采样给出的是一致性数据（实测 75%），这是判断"结论能不能采信"的唯一依据。**建议保留 3 次采样用于评估阶段，等门槛与提示词定稿后、跑生产流量时再降到 1 次 + 只对低置信条目复采。**

## 七、当前能下的结论与不能下的结论

**能下的结论**

1. 链路完全打通：真实照片 → 多模态模型 → 结构化结果 → 指标统计，单次采样约 3 秒／张，3 次采样约 8～12 秒／张。
2. 账号可用型号是 `qwen-vl-max` 和 `qwen-vl-plus`，`-latest` 系列与 `qwen2.5-vl-*` 不可用。
3. **结论一致性 75%**，单次调用不可采信，必须多次采样取多数。
4. **模型不会主动标"不确定"**（36 次判定里 0 次），安全阀必须由产品侧强制。
5. **模型确实在看图且对门槛敏感**，但对"2 个还是 3 个空位"数不准——而业务门槛正好卡在这个区间。
6. **产品经理自己标注会出错**——这既是对照实验的意外收获，也是本功能的价值论据。
7. 用"修正后的、但仍是产品经理自标"的基准，模型在 8 张上召回 2/2、误报 1。**这只能叫"有苗头"，不能叫"验证通过"。**

**不能下的结论**

- ❌ 不能说"模型识别率 87.5%"——基准是我自标的，已证实会错（IMG_1986 是模型对、我错）。
- ❌ 不能说"召回率 100%"——样本只有 1 家店、真缺货只有 2 张，2/2 在统计上毫无意义。
- ❌ 不能说"模型能不能用"——**样本量 12 张、1 家店，且无独立人工基准**。
- ❌ 不能拿任何本轮数字进简历或对外汇报。
