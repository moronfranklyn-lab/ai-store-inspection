## 0. 功能定位与边界

**一句话定位**

> 在远程巡店专员逐张看门店照片的流程里，**让 AI 先把"排面缺货"这一项挑出来并给出证据，专员只复核这一项，不用再自己一张张找。**

**为什么第一个做"排面缺货"**

1. 它是零食连锁门店最高频、最影响销售的偏差（货没摆满 = 直接损失销售机会），业务价值最直接。
2. 视觉特征最明确（连续空位、缺货位无价签），比其他检查项更可判定，最容易做准。
3. 公司已有"把货补满"这类明确的巡店规则诉求，判定标准业务侧能说清楚。

**本功能不负责的部分（明确划出去，避免越界）**

| 不属于本功能 | 归属 |
| --- | --- |
| 其他检查项（陈列、价签、卫生、形象等） | AI 巡店项目的其他功能，各自有产品负责人 |
| 巡店任务的创建、派发、批次与门店分配 | 既有巡店系统的巡店管理与任务体系 |
| 判定结果的得分计算规则、门店奖励与处罚规则 | 门店经营中心既有的标准化考核规则 |
| 整改任务的下发、门店确认、申诉与报备流程 | 既有整改链路 |
| 巡店照片的采集渠道与存储 | 既有图片中心 |
| 摄像头实时视频、边缘算力 | 独立的实时视频巡检能力线 |
| AI 巡店上线节奏、组织推行策略、跨部门协同 | AI 巡店项目负责人 |

**上下游关系**

```text
既有图片中心 ──照片──▶ 【本功能：排面缺货识别 + 专员复核】──疑似问题──▶ 既有整改链路
                          │                                    （由专员确认后才流转）
                          └──被改判/漏检样本──▶ 回流语料（用于本功能迭代）
```

## 1. 目标用户与核心任务

**目标用户**

- **主用户：门店经营中心的远程巡店专员**。每天在系统里逐张看门店照片，判断门店是否达到公司标准化基准。
- **间接使用：门店经营中心负责人**（看本功能的准确率与人工节省是否达到预期，决定是否扩大范围）。

**使用场景**

专员打开一家门店当次的巡店任务，系统里已有该门店的照片。以前他需要把所有照片逐张翻完、自己找出排面缺货的位置；现在打开就有一份**"排面缺货"的建议清单**，他只看清单里标出的照片，逐条确认或纠正。

**要完成的核心任务**

> 让专员复核"排面缺货"这一项的时间，比人工逐张翻照片明显更短（目标：单店这一项节省 8 分钟以上）；同时保证 **AI 不会把不存在的缺货报成缺货**——报错一次，专员就不会再信它第二次。

**这个功能的成败标准只有两条**

1. 专员**敢用**：误报率足够低，不至于让他觉得"还不如我自己看"。
2. 专员**省时间**：确实少翻了一堆照片。

## 2. 输入、过程和产物

**输入**

- 一次既有巡店任务下的该门店照片。JPG/PNG，单张不超过 10 MB，单次任务不超过 40 张。
- 该门店当次任务所属的巡店规则集（对齐公司既有的"把货补满""门店常规巡检"等规则）。
- 该门店基础信息（门店编号、货架区域信息如有）。

**过程**（专员视角）

1. **看到建议清单**：进入任务后，"排面缺货"一项下直接列出 AI 挑出的疑似缺货位置，每条包含：**所在照片、图上标注位置、疑似缺货的层数、AI 给出的判定依据**。
2. **逐条复核**：专员对每条只做三个动作之一——
   - **确认**：确实是缺货 → 计入问题；
   - **改判**：不是缺货（例如是正常排面调整、被顾客遮挡）→ 不计入问题，并计入 AI 误报统计；
   - **补充**：AI 没挑出来但专员自己发现的缺货 → 手工补录一条，计入 AI 漏检统计。
3. **完成本项**：本项复核完成后，结论交回既有流程（得分计算与整改任务由既有体系处理，本功能不参与）。

**输出**

- 一份**"排面缺货"最终结论**：哪些位置确认缺货、哪些被判定为正常、哪些是专员补录的。
- 一份**本项复核留痕**：谁、何时、把哪条从什么改成了什么。
- 一份**本项 AI 表现数据**：建议总数、被确认数、被改判数、被补录数——这是本功能迭代的唯一依据。

**要长期保留的**

- 被改判与被补录的样本（含照片与位置）：用于优化判定口径、提示词与后续模型微调。
- 复核留痕：用于处理"门店不认可判定"时的追溯。

## 3. 主链路与复核交互

```text
进入既有巡店任务（不改任务体系）
  → 读取该门店照片（复用图片中心）
  → 【画面质量预检】过暗/过曝/被遮挡的照片直接标"不确定"，不送模型硬判
  → AI 逐张识别疑似排面缺货位置
  → 多次采样取多数，得到稳定的建议结果
  → 输出建议清单：照片 + 图上区域 + 判定依据 + 置信标记
     层号仅作辅助提示，不作为结论（依据见下方）
  → 专员逐条复核：确认 / 改判 / 补充
  → 本项结论交回既有流程（得分与整改由既有体系处理）
  → 改判与补录样本回流语料池
```

**规则细节（产品负责人需要定死的部分）**

| 规则 | 本功能结论 | 理由 |
| --- | --- | --- |
| **判定粒度** | **报告到"证据照片 + 货架区域"，不把层号当结论**（层号仅作辅助提示） | **实测：模型判断"有没有缺货"准确率 91.7%，但"是哪一层"只有 60%。层号报错会让店长白跑一趟，直接摧毁信任**——见《实验发现 02》 |
| 报几条 | 同一层连续空位合并为一条，不逐空位报 | 逐空位报会让清单爆炸，专员复核时间反而变长 |
| 低于门槛怎么办 | 空位数低于判定门槛的不报（视为正常排面调整） | 报太多无效项会直接摧毁专员对本功能的信任 |
| 看不清怎么办 | **不靠模型自觉标"不确定"，由画面质量预检强制标注** | **实测：模型 36 次判定中 0 次主动标"不确定"**，即使画面被购物篮挡住大片也照给确定结论。安全阀必须在产品侧用确定性逻辑强制 |
| 采样策略 | 同一张照片采样 3 次取多数 | **实测：单次采样层号噪声率 13.3%，结论一致性 91.7%**；多数表决把"位置严格一致 60%"提升到"多数稳定 80%" |
| 证据要求 | 每条必须能指到具体照片与图上位置 | 没有证据的结论，专员和门店都不会认 |
| 置信度展示 | 对专员展示置信高低（低置信排在后面或标灰） | 让专员把注意力放在高价值条目上，提升复核效率 |

**为什么判定粒度要从"按层"改成"照片＋区域"（一次由数据推动的产品决策）**

原始设计是"按货架层报告"，理由是"门店整改要知道补哪一层，整店一条无法执行"。这个推理本身没问题，但实测数据不支持：

- 模型判断"这张照片有没有缺货"：准确率 91.7%、精确率 100%（12 张样本）
- 模型判断"缺的是哪一层"：**层级准确率仅 60%**（3/5 张）
- 单次调用层号噪声率 13.3%，即约每 8 次调用就有 1 次层号是错的

**如果继续按层给结论，约 40% 的情况店长会照着错层号去补货、白跑一趟，然后不再信任这个功能。** 因此改为：AI 负责**定位到照片并圈出区域**（这是它可靠的部分），层号降级为辅助提示，由专员或店长看证据照片自行确认。

> 这条改动的意义不在改动本身，而在于：**产品方案是被实测数据推翻并修正的，不是拍脑袋定的。** 详见 `experiment/docs/实验发现02-双店样本最终结论.md`。


**哪些步骤必须用户确认**

- AI 建议清单 → 本项最终结论：**必须**由专员确认。AI 输出只能叫"疑似缺货"，不能叫"缺货"。
- 结论 → 任何考核/整改动作：由既有体系处理，**本功能不发起任何自动流转**。

**关于 AI 不可用**

- AI 识别失败或超时，专员必须能按原有方式（自己翻照片）完成本项复核。**本功能不得成为巡店流程的单点故障**。

## 4. 什么算"识别得好"

**好的结果长什么样**

1. **挑得准**：报出来的疑似缺货，绝大多数是真的。
2. **指得清**：每条都能指到哪张照片、哪一层、什么位置。
3. **说得明**：每条有一句可读的判定依据（如"该层连续 5 个空位且无价签"）。
4. **该闭嘴时闭嘴**：看不清就标"不确定"，空位不足门槛就不报。
5. **让人更快**：专员复核本项的时间确实比人工翻照片短。

**允许的瑕疵**

- 少数误报可接受（专员会改判）。
- 漏掉个别边缘位置（如照片边角、被遮挡的层）可接受。
- 措辞与格式不统一可接受。

**不能接受的**

- 把正常排面报成缺货，且证据里看不出问题 → **最容易失去专员信任**。
- 把"不确定"包装成确定结论。
- 漏掉整张照片、整层货架。
- 编造照片里不存在的位置。

**怎么验收（本功能的产品负责人负责定）**

1. **取真实样例**：从不同区域、不同门店形态（社区店/商圈店）、不同光线条件下取 **10 家门店、每家 20～30 张真实巡店照片**。
2. **组织打分**：由远程巡店专员逐条标注"AI 说对了 / 说错了 / 漏了"，并记录复核耗时。
3. **用打分反推**：确定判定门槛（连续几个空位才算缺货）、确定哪些门店形态/光线条件下当前不可靠、确定需不需要把某些照片类型（如极暗、强反光）排除出识别范围。
4. **验收看三条线**：
   - **误报率**：低于什么水平专员才愿意用（用第一步的真实打分定，不预设数字）。
   - **"不确定"是否诚实**：有没有该标不确定却硬给结论的情况。
   - **单店本项复核耗时**：是否比人工方式节省 8 分钟以上（对齐集团 AI 巡检公开口径）。
5. **外部对标方向**：同业公开的 AI 巡店案例中有准确率做到 95% 的（AI 巡店在连锁零售的落地案例）。**本功能不预设这个数字**，只作为后续优化方向。
6. **一致性检查（2025 年模型的现实限制）**：同一批照片连跑两次，结论差异率不能过高。视觉语言模型目前对"连续几个空位"这类计数与边界判断并不稳定，如果同一家门店每次跑出来的结论都不一样，专员就无法建立对它的信任——这条必须在验收时单独测。

## 5. 交付阶段与优先级

**第一版必须有**

1. 接入既有巡店任务与照片（复用图片中心，不新建采集通道）。
2. 识别疑似排面缺货位置，输出建议清单（照片 + 位置 + 层数 + 依据 + 置信标记）。
3. 逐条复核：确认 / 改判 / 补充，全程留痕。
4. 本项结论交回既有流程。
5. 本项 AI 表现统计（建议数、确认数、改判数、补录数）。
6. AI 不可用时可退回人工方式完成本项。

**第一版不做**

| 暂缓项 | 原因 |
| --- | --- |
| 其他检查项 | 其他功能负责人的范围 |
| 实时视频流识别 | 独立能力线 |
| 无人复核的自动判定 | 判定直接关联门店考核，必须先积累被确认率数据 |
| 自动生成整改任务 | 属既有整改链路 |
| 按门店形态自适应的判定门槛 | 等第一版真实打分数据出来再做更稳 |
| 门店端自助查看 AI 识别结果 | 既有链路已处理，避免引发门店直接对 AI 判定的争议 |

**下一步迭代方向**：把高被确认率的场景从"建议"升级为"自动判定 + 抽检" → 按门店形态与光线条件自适应判定门槛 → 与实时视频巡检打通，覆盖两次巡店之间的空档。

## 6. 模型能力约束（对齐 2025 年可用技术）与成本

**为什么这件事是 2025 年才做得成**

- 2025 年多模态模型进入 **VLM 2.0** 阶段："高分辨率 + 动态切图"让模型看得清货架小目标，**原生多图理解**让一次巡店的多张照片能放在同一个上下文里判断，"同一层连续空位"这种带计数的指令第一次能被模型大致执行。
- 在此之前的小模型路线做不到这种泛化：每加一个检查项都要重新标数据、重新训练。**VLM 第一次让"改判定口径不用改模型"成为可能**——而连锁零售的检查表是常态调整的。
- 但也必须承认 2025 年 VLM 的三个现实限制，它们直接影响本功能的产品设计：
  1. **计数与边界判断不稳**：模型对"连续几个空位"、"这一层到底有没有空"容易数错；
  2. **对光照与角度敏感**：偏暗、强反光、斜拍的照片误报明显上升；
  3. **结论不可复现**：同一张图多次推理可能给出不同结论。
- 对应的产品对策：**判定门槛设保守 + 无法判定就标"不确定" + 后台多次采样取多数 + 后台预跑**。这些约束是为了让不确定性在流程里被吸收，而不是暴露给专员和门店。

**模型选型约束**

- 只用**国内可合规调用**的多模态视觉模型，不引入境外 API（门店照片可能含顾客与员工影像，出境有合规风险）。
- 候选分三类，按 2025 年的可得性排列：
  - **国产闭源多模态 API（优先）**：通义千问 Qwen-VL 系列、豆包 Doubao-vision 系列、智谱 GLM-4V 系列。支持多图理解、结构化输出、有企业级数据合规条款，接入成本最低。
  - **开源可私有化部署（备选）**：Qwen2.5-VL 系列、InternVL 系列。优点是可完全不出内网，代价是要自己承担推理算力与运维。
  - **海外闭源多模态**：**不采用**，仅作为效果上限的参照。
- **不预设具体型号**：候选中哪一款，要用真实样例实测后选，判断依据是"误报率可控、能稳定输出结构化结果、单次成本达标"，而不是参数规模或榜单分数。
- 禁用：会把门店照片用于训练的免费/公开服务；无法确认数据落地的第三方。

**成本约束**

- 单次巡店照片的识别费用目标不超过 **0.2 元**（本功能只跑"排面缺货"一项，成本低于整表识别）。
- 成本控制手段：只重跑受影响的照片、跳过明确无货架内容的照片、后台批量处理。
- 任何单次调用超过 0.5 元、或新增付费第三方服务，需先向项目负责人说明再动手。

## 7. 数据与非功能要求

- 照片属公司内部资料，可能含顾客面部与员工影像：**数据存放国内、不进境外模型、不写入日志、不用于模型训练**。具体合规规范沿用公司既有要求。
- 响应时间：单张照片识别结果 10 秒内可见；一家门店 30 张照片的本项识别 2 分钟内完成；建议清单应在专员打开任务前**后台预跑就绪**，不让专员等。
- 文件限制：单张 JPG/PNG ≤ 10 MB，单任务 ≤ 40 张；校验真实文件类型与大小。
- 持久化：任务、复核结论、留痕、AI 表现数据在关页面/断网/服务重启后都不能丢。
- 增量与兜底：AI 不可用时不影响专员按原方式完成复核。
- 留痕可追溯：每条结论可回溯到原始照片与当时的 AI 依据；因判定引发的门店申诉可查到当时依据与是否被改判。

## 附 1："排面缺货"检查项定义（我在检查表中的那一条）

| 字段 | 内容 |
| --- | --- |
| 检查项编码 | `SHELF_OOS` |
| 检查项名称 | 排面缺货 |
| 所属类别 | 货架与库存 |
| 适用规则集 | 把货补满 / 门店常规巡检 |
| 判定依据 | 同一层货架出现连续 3 个及以上空位，且无价签或商品遮挡，判为缺货 |
| 合格标准 | 空位少于 3 个视为正常排面调整，不判定 |
| **判定粒度** | **报告到"证据照片＋货架区域"；同一层连续空位合并为一条；层号仅作辅助提示**（原为"按货架层报告"，经实测层号准确率仅 60% 后降级，见第 3 节） |
| 采样策略 | 同一照片采样 3 次取多数（单次调用不可采信） |
| 严重程度 | 高（由门店经营中心定义） |
| 是否必须照片证据 | 是 |
| 无法判定时 | **由画面质量预检强制标"不确定"交专员复核**，不依赖模型自觉标注 |

## 附 2：一条真实示例

**场景**：远程巡店专员打开"某某店"当次任务，共 28 张照片，本项识别已后台预跑完成。

**AI 建议清单（排面缺货）**

| # | 照片 | 位置 | 层数 | 判定依据 | 置信 |
| --- | --- | --- | --- | --- | --- |
| 1 | 照片 7 | 图中中部偏左 | 第 2 层 | 连续 5 个空位且无价签 | 高 |
| 2 | 照片 12 | 图中右侧 | 第 2 层 | 连续 4 个空位 | 高 |
| 3 | 照片 20 | 入口堆头 | — | 堆头仅剩底部两层 | 中 |
| 4 | 照片 9 | 图中上部 | 第 4 层 | 疑似空位，画面偏暗 | 低 |

**专员复核**

- 确认 #1、#2、#3。
- 改判 #4：现场确认是阴影，不是空位 → 计入 AI 误报。
- 补充：照片 5 第 3 层有连续空位，AI 未识别 → 计入 AI 漏检。

**本项结果**：确认缺货 3 处、改判 1 条、补录 1 条。本项结论交回既有流程；改判与补录样本回流语料池。本项复核耗时约 3 分钟（原人工方式约 11 分钟）。

## 附 3：我作为本功能产品经理的关键决策

| # | 决策 | 结论 | 理由 | 放弃了什么 |
| --- | --- | --- | --- | --- |
| F1 | 判定粒度按整店还是按层 | **按货架层** | 门店整改要知道补哪一层，整店一条无法执行 | 输出条目更多，需要合并规则 |
| F2 | 空位不足门槛要不要报 | **不报** | 报太多无效项会直接摧毁专员信任，信任没了这功能就废了 | 会漏掉一些轻微的缺货情况 |
| F3 | 允不允许"不确定" | **必须允许且强制交人工** | 硬猜出的结论会变成门店申诉的源头，一次申诉抵掉十次效率收益 | AI 结论覆盖率看起来变低 |
| F4 | 识别结果要不要自动转整改 | **不自动，由既有流程处理** | 判定直接关联门店考核，不可逆动作不能由 AI 触发 | 少了"自动闭环"的卖点 |
| F5 | 复核的改判算谁的错 | **不算专员的负面记录，只计入 AI 表现统计** | 改判是本功能迭代的弹药，要鼓励而不是抑制 | 需要额外实现样本回流 |
| F6 | 要不要给门店看 AI 识别结果 | **第一版不给** | 避免门店直接与 AI 判定争辩，先把专员侧的信任和准确率做起来 | 门店侧少一个自查工具 |
| F7 | 判定门槛先固定还是自适应 | **先固定，用真实打分再决定** | 没有真实数据前做自适应是空想 | 不同门店形态初期表现不均 |

## 附 4：待确认事项

1. **"排面缺货"的判定门槛**（连续几个空位算缺货、是否区分门店形态）需门店经营中心确认——这决定误报率与专员信任。
2. **本功能的照片来源**：确认只取既有巡店任务的照片，且第一版只覆盖远程巡店。
3. **识别结果在系统中的挂载位置**：挂在既有巡店任务的哪个页面/入口，需与既有巡店系统的对接方确认。
4. **AI 表现数据是否对门店经营中心开放**：建议开放，供业务侧判断口径是否需要调整。
5. **真实照片样例**（至少 10 家门店）能否按期拿到，决定"用真实打分定验收标准"能否落地；照片中顾客/员工影像的处理规范由哪一方负责。
6. **模型选型与结算方式**：是否优先用公司既有 AI 合作方的模型、费用是否走公司云账号。
